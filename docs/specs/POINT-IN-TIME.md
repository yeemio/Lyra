## 1. 合同范围

本合同管三件事：

1. **时点语义**：一条事实"何时可知"的表示（五时间字段）、as-of 读取判定、修正关系（supersedes）。
2. **封存**：研究输入 manifest 的内容、不可变性与读取边界。
3. **原件库**：CAS 内容寻址存储合同（写入、校验读、区间读、不可变、隐私级）。

明确不管：

- 执行与模型调用（permit、send-once、UNKNOWN、恢复）——`docs/specs/EXECUTION-KERNEL.md`；
- 数据源适配器行为（抓取策略、限流退避、三层回填、来源优先级）——`docs/specs/DATA-SOURCES.md`；
- ST 时点表与涨跌停判定等 A 股域规则本体——`docs/specs/ASHARE-RULES.md`（其时间机制复用本合同 §2 的字段与判定）。

分层定位（`docs/ARCHITECTURE.md` 数据层/时点层）：适配器把原件写入原件库并产出事实；时点层按本合同做 as-of 过滤与封存；研究层不直接触碰数据源，只读封存 manifest 指向的内容。层间依赖单向向下。

## 2. 五时间字段模型

### 2.1 记录形态

每条事实至少有（字段沿 Metis SPEC §6，语义 A 股化；`parser_version` 在 Lyra 更名 `adapter_version`，对应"数据与适配器版本轴"）：

```text
fact_id / subject_type / subject_id / fact_kind / typed_value
valid_from / valid_to                  适用期（事实描述的期间），允许 unknown
event_at / event_time_precision        事件时间与精度（时刻 / 日）
source_published_at / published_basis  来源发布时间与依据（巨潮公告时刻、BaoStock pubDate）
first_observed_at / recorded_at        首次实际取得 / 正式入库时间
available_at                           该版本事实已持久化且可供读取的确认时间
source_evidence_ref / source_hash / adapter_version
supersedes_fact_id / conflict_group_id / quality_state
```

| 字段 | 含义 | A 股示例 |
|---|---|---|
| valid_from / valid_to | 适用期 | 三季报事实 valid_from = 报告期起始日；申万 2014 版分类 valid_to = 2021 版生效前一日 |
| event_at | 事件发生时间 | 报告期截止日、除权日、成分调整生效日 |
| source_published_at | 来源方标注的发布时间 | 巨潮公告时刻、BaoStock pubDate |
| first_observed_at / recorded_at | 我方首次实际取得 / 入库 | 回填批次的实际抓取日期 |
| available_at | 可供读取的确认时间 | 取法见 §2.2 |

判定：事实不可原地改（typed_value 与 source_hash 写入后只读）；subject/kind/available_at 可索引检索。

### 2.2 available_at 的取法与三条禁令

available_at 的原义（沿 SPEC §6）：**该版本事实已持久化且可供读取的已确认时间**。运行中实际取得的事实（取得态）照此执行：写入结果未知时不得提前标记可用，登记完成才算。

A 股约定（§3 详述）：**公告类事实以来源法定披露平台记录的发布时刻为 available_at 基准**，历史回填与线上取得一致适用；recorded_at 仍如实记录实际入库时间，两字段并存——审计时能看出"该事实是后来回填的"。该基准的合法性依据：巨潮是法定信息披露平台，公告时刻即信息进入公共可得状态的时刻；这是一条**声明过的近似**，仅限 §3 列明类别。线上封存最终以 run 的实际输入 manifest 为准（§7），可得性基准主要用于历史重建与回放。

三条禁令（均可验收）：

1. **available_at ≠ source_published_at ≠ 事务时间**。判定：三者是记录中互不覆写的独立字段。
2. **来源写旧日期、系统后来才取得，不得伪装当时已知**。判定：取得态非公告类事实的 available_at ≥ first_observed_at；除 §3 列明类别外，任何事实不得以来源标注的旧日期作为可得时间。
3. **缓存命中不更新 first_observed_at，不把读取时间当发布时间**（沿 SPEC §6.2）。

### 2.3 as-of 读取判定

- 封存截点 C（knowledge_cutoff_at）下，只读 `available_at <= C` 且适用期覆盖目标日期（valid_from/valid_to 命中）的事实。判定：读回结果出现任何 available_at > C 的事实即泄漏违约。
- `source_published_at <= C` 单独不构成可读——来源标注不等于我方可得（沿 SPEC §6.1）。
- 事件时间只有日精度的，不捏造时刻（沿 SPEC §6.1"不捏造开球秒数"），按 §3 日精度规则处理。
- 派生特征（行业超额收益序列、历史参照群组等）必须绑定输入最大可用时间、计算方法版本与实际 materialized_at；截点后重算标记 replay，不冒称当时已用（沿 SPEC §6.1）。
- 缓存键必须含精确截点（形如 `subject + 用途 + knowledge_revision + 特征版本 + exact_query_cutoff`）；不得因同属一个时间桶而混入稍晚事实（沿 SPEC §6.2）。

## 3. A 股时点约定

1. **公告类事实**：巨潮公告时刻为 available_at 基准。有披露时刻的按时刻；历史回填中仅有日精度的公告（无时刻），保守按公告日**次一交易日开盘前**可得（D+1 开盘前）。判定：日精度公告的 available_at 不得早于 D+1 开盘前时点；截点在 D 当日收盘后的封存看不见它。
2. **结构化财务（BaoStock 季频）**：按 `pubDate` 做时点读取；pubDate 只有日精度，同样按 D+1 开盘前保守处理。`statDate`（报告期）只进 valid_from，**不定可得性**——按报告期归档、忽略 pubDate 是最典型的泄漏错误（§5.1）。pubDate 标注的是数据版本的发布日，其数值受 §6 修订口径约束。
3. **预约披露时间表**：交易所每季度公布的预约披露日期表，本身是一条可时点化事实——available_at = 该版预约表的公布时间，适用期覆盖其对应季度。事件前研究以预约日为主触发〔R9〕，因此历史封存日期 D 只能用"D 当时已公布的预约表版本"；用最终实际披露日回填预约表，等于把未来泄漏进事件前研究。预约表自身的推迟/提前调整走 §4 supersedes。
4. **其余来源**：交易所官网函件、融资融券、龙虎榜等按发布日（日精度 → D+1 开盘前）；行业分类版本与指数成分按其版本事实的生效日期（§5.2、§5.3）。

## 4. 修正与 supersedes

- 修正是**新增事实及关系，不覆盖原事实**：新事实带 `supersedes_fact_id` 指向被修正事实，同 `conflict_group_id` 并存。判定：修订链上所有原件与旧事实保持可解析。
- 走 supersedes 链的 A 股情形（不限于）：业绩预告更正公告（上修/下修，作为预告事件子类，不另立类型〔R10〕）、财报重述、退市整理期相关的修正性披露、预约披露表的调整。
- **同原件重复抓取**：相同 bytes 且适配器版本不变时，只增加观察收据（记录一次新的观察时间），不重做语义计算（沿 SPEC §6）。判定：同一原件 + 同一适配器版本重放，不产生新 fact_id。
- **适配器合同变更**：可用同一原件生成新事实版本（新 fact_id、新 available_at、新 adapter_version），旧事实保留——解析合同演进不重写历史。
- **来源冲突**（巨潮与交易所官网、BaoStock 与公告原文）：不自动相互覆盖，conflict_group_id 并存并暴露依据；关键数字以公告 PDF 原文交叉核对（`docs/PLAN.md` §3）。人工裁定时记录裁定者、依据与有效期。

## 5. 四类时点对象（泄漏测试对象）〔R14〕

每类给出"误用当前值回填历史"的具体错误与正确做法；每类至少一例合成用例进入泄漏测试（§8）。

### 5.1 公告/财务发布时间

- 错误：重建 2018-10-25 的研究封存时，"2018 年三季报营收"按 statDate（2018-09-30）归档，导致 10-25 已可读——而该财报实际 10-27 才披露，读回了两天后的未来。
- 正确：statDate 只进 valid_from；可得性只看 available_at（巨潮公告时刻 / pubDate+D+1）。判定：封存截点早于披露时点时，该财报事实对读取不可见。

### 5.2 行业分类版本〔R8〕

- 错误：用申万 2021 版分类与对应指数回填 2018 年的行业归属与行业超额收益——该公司 2018 年按 2014 版属于另一行业，行业基准口径错位，超额收益系统性失真。
- 正确：2015–2021 区间用 2014 版分类与对应指数，之后用 2021 版；版本生效日作为分类表事实的 valid_from 登记；切换后的样本不回溯重分类、不用新版本重解释旧样本。

### 5.3 指数成分归属〔R16a〕

- 错误：用今天的中证 800 成分表重建 2019 年的股票池与市场状态判定——2019 年在列、现已调出或退市的股票被漏掉，之后调入的被混入（幸存者偏差 + 成分错位）。
- 正确：按日期重建——BaoStock 沪深 300 与中证 500 按日期成分查询，中证 800 = 两者在该日期的并集；每次成分调整是带生效日期的事实链。判定：日期 D 的成分集合只能由生效日 ≤ D 的调整事实导出。

### 5.4 复权因子

- 错误：用含 2020 年送转除权因子的后复权序列判定 2018 年某日一字板——未来除权信息混入历史价格，四价比较与当日涨跌停价对不上〔R7：一字板判定必须用不复权原始价〕。
- 正确：原始价与复权因子分开存、分开读；因子按除权日生效（valid_from = 除权日），日期 D 的累计复权只用除权日 ≤ D 的因子——结构上天然避免前视；结算需要后复权口径时按此逐日合成，原始价始终可独立读回。

## 6. 修订口径声明〔R4〕（原文）

> **修订口径声明：一次性回填 2015–2026 拿到的是当前最新修订值，与当时公告值可能不同且不可复原；历史参照库的事件主证据以公告 PDF 原文为准，结构化数据做辅助。**

醒目要求：该声明必须**原样**出现在所有消费回填结构化财务的输出中——历史参照库报告、研究封存摘要、界面展示模板——不得改写、不得省略。判定：消费方合同（`docs/specs/HISTORICAL-REFERENCE.md`、`docs/specs/RESEARCH-METHOD.md`）与输出模板中可检索到上述原文；回填结构化数字旁标注"最新修订口径"。

## 7. 封存合同

研究输入以 manifest 封存（沿 SPEC §6.1"线上封存以 run 的完整输入 manifest 为准"）。manifest 至少包含：

1. **资料清单**：每份资料的原件哈希（source_evidence_ref）与事实引用；
2. **读取截点**（knowledge_cutoff_at）：本次研究可见世界的上限；
3. **显式缺口列表**：封存时已知缺失的资料（来源未覆盖、首版后置项等），逐一列名，不静默忽略（对应 `docs/PLAN.md` §6"资料不全时照常研究，但写明缺口"）；
4. **三条版本轴**：方法版本 / 数据与适配器版本 / 执行计划与授权版本（`docs/ARCHITECTURE.md` 约束 3）；
5. **实际创建时间**与未解决冲突引用。

判定：

- 研究全程（A、程序清单、J）只读 manifest 指向的内容；出现 manifest 外的事实引用即违约。
- 封存后 manifest 与其指向的原件、事实不可变；被引用对象不得删除或改写，旧 run 永远可解析。
- manifest 内所有引用可解析：每个哈希都能从原件库读回且校验一致。

## 8. 泄漏测试

- **形态**：程序化可执行的测试，不依赖人工目检。流程：任选历史日期 D 封存 → 读回 → 断言读回内容（事实、派生特征、展示层）中没有任何 available_at > D 的信息。
- **合成用例**：四类时点对象各至少一例（〔R14〕）；§5 各类的"错误示例"即用例注入方向——测试数据中故意埋入 D 之后发布的事实，断言被 as-of 过滤挡住。
- **地位**：泄漏测试是旅程测试的组成部分，因此是安装门的组成部分（`docs/ARCHITECTURE.md` 约束 4、`docs/specs/P0-FOUNDATION.md` Done-when）；同时是 P1 数据阶段的停止条件——"30 个标的的研究池加中证 800 主板覆盖能按任意历史日期完整封存，且不泄漏未来信息"（`docs/PLAN.md` §8）。
- **边界用例**（至少各一例）：截点当日的公告（时刻可得与日精度 D+1 两种路径）；预约披露表的版本切换。

## 9. 原件库

合同形态继承 Metis `packages/storage/src/artifacts.ts`（参考实现；移植或重实现均须满足以下全部条款）：

1. **CAS 内容寻址**：以内容 sha256 为唯一身份，存储目录按哈希前 2 位十六进制分片。判定：同 bytes 必得同哈希同引用；不存在按语义命名的主存储路径。
2. **写入即校验**：写入走临时文件 → 持久化（sync）→ 以目标哈希读回校验一致，才算成功；同哈希重复写入幂等，不产生第二份内容。判定：写入调用返回后，立即按哈希读回，字节与哈希一致。
3. **哈希校验读**：每次读回重新计算哈希与目标比对，不符即报 HASH_MISMATCH，不返回可疑内容；符号链接路径拒绝。
4. **字节区间读**：支持 `(start, limit)` 区间读取，返回区间字节、区间哈希、total、truncated 与 nextCursor——大 PDF 摘录（研究只需某几页）不整份载入。判定：区间读结果与全量读的对应切片逐字节一致。
5. **不可变**：无更新、无覆盖路径；事实修正只在事实层走 supersedes（§4），原件永不改写。删除只有显式隐私清除通道且留 tombstone（沿 Metis erasePrivate 语义；Lyra 首版可不实现，但不得提供任意删除）。
6. **隐私级**：个人研究数据默认私有——本地目录/文件权限收紧（0700/0600 量级），原件不外传（`docs/PLAN.md` §9 合规边界）。

**入库范围**（全部带抓取时间 first_observed_at）：公告 PDF、行情原始行（未复权日线）、复权因子、行业分类表（分版本）、指数成分表（按日期）。判定：任何进入研究封存的内容都能追溯到一个带哈希的原件及其抓取时间。
