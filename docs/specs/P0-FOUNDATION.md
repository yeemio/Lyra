# P0 底座 — 实施合同（第一份）

状态：**v1 已冻结，2026-10-25**（审阅记录 `docs/FREEZE-P0-20261025.md`）。依据：`docs/PLAN.md` v1.1 §8、§10；修订 R1、R5、R14、R19、R21。上位合同：`docs/ARCHITECTURE.md`（结构约束与简化内核边界）、`docs/specs/EXECUTION-KERNEL.md`（旅程测试安装门见 §10）、`docs/specs/POINT-IN-TIME.md`、`docs/specs/ASHARE-RULES.md` §2.1、`docs/specs/RESEARCH-METHOD.md` §3/§8。

## Goal

建立 Lyra 的工程底座：在**无任何真实数据源、无任何真实模型调用**的条件下，用模拟模型与合成数据跑通"封存 → A → 程序清单 → J → 结论对象落库 → 结算骨架"的完整旅程，且旅程测试作为安装门全绿。

## Done-when（可观察停止条件）

全部满足即停，不追加范围：

1. **旅程测试全绿**（模拟模型）：`EXECUTION-KERNEL.md` EK-10.2 的七项断言是唯一权威清单，全部实现并通过；另补以下 P0 断言：
   - **输入超预算阻断**：超过输入预算的封存输入以 `INPUT_OVER_BUDGET` 具名阻断，permit 不进 SENT、不截断；修复后同键重试最终发送次数为 1（EK-4.4/4.5）。
   - **泄漏测试边界用例**：四类时点对象各至少一例之外，覆盖截点当日公告的两条路径（有时刻 / 日精度 D+1）与预约披露表版本切换（`POINT-IN-TIME.md` §8）。
   - **涨跌幅规则表切换**：同一合成 ST 主板股在 2026-07-03 取系数 5%、2026-07-06 取 10%，一字板判定随之变化；规则表命中零行或多行时报具名错误（`ASHARE-RULES.md` §2.1〔R19〕）。
2. **唯一执行器与并发**：第二个执行器进程的任何执行操作被 `EXECUTION_LOCK_HELD` 拒绝；任意时刻在途模型调用 ≤ 2，由 permit 表按时间窗断言（EK-2.1、EK-2.3）。
3. **启动诊断与恢复**：冷启动失败时诊断信息可见（缺什么、什么状态、下一步）；中断后重启进入 RECONCILING，零模型调用；恢复需显式确认，确认后检查点、permit、研究对象三者一致（EK-8）。本地退役只经 Owner 显式确认触发，不设自动退役（R21）。
4. **三条版本轴落地**：方法版本、数据与适配器版本、执行计划与授权版本在存储中是三个独立身份字段；旅程测试断言改任一轴不隐式改变其他轴。
5. **研究结论对象**：`RESEARCH-METHOD.md` §8 全部字段齐备，且字段间程序校验生效——disposition 等于 J 最终决定；四个证据哈希缺一不可、清单哈希可由 A 输出机械重导出；继承指针与改判理由的配对约束；adoption 恒 false；结算占位区初始"未结算"且回填不改研究字段。两类标的的选项空间分别校验：个股只允许 `RESEARCH_OUTPERFORM / RESEARCH_UNDERPERFORM / ABSTAIN`，宽基只允许 `RESEARCH_UP / RESEARCH_DOWN / ABSTAIN`，跨类即拒绝〔R18〕。
6. **安装门留痕**：安装流程运行旅程套件，并把全绿记录（版本标识、测试运行标识与输出摘要、时间）写入安装日志；无全绿记录的安装视为未完成（EK-10.3）。

## 非目标（P0 明确不做）

- 真实数据源适配器（P1）；真实模型调用（P2 起按有界授权）；方法全文、八维度与宽基七维（P2）；公告检测与调度（P3）；历史参照库（P4）；正式采用与资金结算（首版全范围不做）。
- 方法资格链 / graph release / 多方法注册机器（首版不建，见 `docs/ARCHITECTURE.md` 裁剪声明）。
- 界面（P0 只需命令行/测试可读回；UI 在后续阶段）。

## 范围与工件

| 工件 | 内容 | 合同 |
|---|---|---|
| 原件库 | CAS 内容寻址存储、哈希校验读、字节区间读、不可变写入 | `specs/POINT-IN-TIME.md` §9 |
| 时点读取 | 五时间字段、as-of 过滤、封存 manifest、四类时点对象 | `specs/POINT-IN-TIME.md` |
| 执行内核 | 唯一执行器、permit、send-once、输入大小阻断、UNKNOWN 状态机与本地退役、截止自身持有、并发上限 2、恢复 | `specs/EXECUTION-KERNEL.md` |
| 涨跌幅规则表 | 带生效区间的系数表与取值算法（合成数据驱动，P1 接真实 ST 时点表） | `specs/ASHARE-RULES.md` §2.1 |
| 研究结论对象 | §8 全字段与字段间校验，个股与宽基两类选项空间 | `specs/RESEARCH-METHOD.md` §3、§8 |
| 旅程测试框架 | 模拟模型、EK-10.2 断言与上述补充断言、安装门接线 | `specs/EXECUTION-KERNEL.md` §10 |

模拟模型的输出形态：A 至少含候选决策、决定性连接（含证据引用）、最强反证、信心与限制；J 至少含逐项 reviews（verdict + decision_bearing）、decision_audit、最终 decision 与 `input_hash` 回抄。字段名沿 `RESEARCH-METHOD.md` §2；P2 接真实模型时 schema 变化以新适配器版本吸收，不动 P0 内核。

## 技术栈（R21 冻结）

TypeScript + Node 24 + PostgreSQL + `node:test`（经 `tsx` 运行），与 Metis 一致，以最大化复用其 permit、执行租约与恢复的已验证形态。执行权凭据用 PostgreSQL 租约（行锁或 advisory lock），send-once 由业务键唯一约束兜底。

环境前置：本机 Node v24.18.0 已就绪；**PostgreSQL 未安装**。安装属系统级变更，P0 第一步须 Owner 明示同意后执行；未安装时冷启动诊断必须具名报出缺失项（Done-when 3）。

## 顺序与工期

内部顺序：环境与诊断骨架 → 原件库 → 时点读取与封存 → 执行内核 → 规则表与结论对象 → 旅程测试整合与安装门。粗略工期 2–3 周；其中执行内核（含 UNKNOWN/恢复语义）是最大单项，预计占一半。

## 风险与已知取舍

- 简化内核省略了 Metis 的资格链机器，意味着方法演进（若发生）需要新的版本轴追加而非原地切换——这是接受的取舍，P5 前无此需求。
- 业务键不含方法版本（EK §12 未决 1）：首版方法冻结期内无冲突，P5 后若需同键重研再修订键定义。
- 截止比较在 P0 使用本地时钟；交易日历校准与漂移容忍（SC-10.3）随 P3 接入，P0 不做时钟偏差注入。
