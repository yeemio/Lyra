## 1. 合同范围

本合同定义各数据源的**用途、主次来源、时点处理、适配器版本规则、回填分层与限流退避**。

**覆盖口径〔R17〕**：本文"中证 800"一律指"中证 800 历史成分中的沪深主板股票"（含已调出、已退市）；创业板、科创板、北交所证券在准入时按代码段与板块字段拒绝（`ASHARE-RULES.md` §1）。成分查询本身仍取完整的沪深 300 / 中证 500 成分，过滤在入库后按板块执行，以便核对与审计。

明确不管：

- **时点语义本体**（available_at 取法、as-of 判定、supersedes 链、泄漏测试）——`docs/specs/POINT-IN-TIME.md`；本文各来源的"时点处理"只是该合同 §3 A 股约定在具体来源上的落点；
- **业务语义**（什么构成事件、涨跌停怎么判、行业基准怎么选）——`docs/specs/ASHARE-RULES.md`、`docs/specs/RESEARCH-METHOD.md`、`docs/specs/HISTORICAL-REFERENCE.md`；适配器不决定业务语义（§6）；
- **调度与执行**（采集任务何时启动、执行器并发治理）——`docs/specs/SCHEDULING.md`、`docs/specs/EXECUTION-KERNEL.md`；本合同只管数据源侧的限流退避行为（§7）。

分层定位：适配器把原件写入原件库并产出带时间字段的事实；时点层按 POINT-IN-TIME 做 as-of 过滤与封存；研究层不直接触碰数据源。

### 2.1 公告与财报原文

- 主来源**巨潮资讯网**（证监会指定法定信息披露平台）；校验来源为上交所、深交所官网的披露页——两者是独立渠道，关键披露以原件交叉核对，冲突不自动覆盖（POINT-IN-TIME §4 来源冲突）。
- 时点：以平台记录的**公告发布时刻**为 available_at 基准（POINT-IN-TIME §3.1）；仅日精度的历史公告保守按 D+1 开盘前可得。
- 原件：**PDF 原件入 CAS 原件库**（POINT-IN-TIME §9），抓取时间 first_observed_at 随件登记；更正/补充公告走 supersedes 链，原件永不覆盖〔R10〕。
- 回填按 §4 三层分层，不做一次性全量 PDF 回填〔R16c〕。

### 2.2 结构化财务指标

- 主来源 **BaoStock 季频接口**（盈利、成长、偿债等，带发布日期 `pubDate` 与报告期 `statDate`）；校验方式为**财报原文抽查**（对研究池股票按比例抽查关键科目）。
- 时点：按 **pubDate** 做时点读取（pubDate 日精度 → D+1 开盘前）；`statDate` 只进 valid_from，不定可得性（POINT-IN-TIME §3.2）。
- 数值受 §5 修订口径声明约束：回填拿到的是来源当前最新修订值，事件主证据以公告 PDF 原文为准。

### 2.3 业绩预告与快报

- 巨潮公告原文与 BaoStock 预告/快报接口**互为主校验**；按公告时间做时点。
- 预告更正公告（上修/下修）作为预告事件的子类，走 supersedes 链，不另立类型〔R10〕。
- 历史参照库六类事件中的预告/快报事件用"巨潮元数据 + BaoStock 接口"即可构建（§4 L1），不等全量 PDF〔R16c〕。

### 2.4 日线行情与复权因子

- 主来源 **BaoStock**；校验来源 **AKShare**（底层为东方财富等公开接口）——校验对象是抽样日的 OHLC 与成交量，不是逐行全量比对。
- **原始价（不复权）与复权因子分开存储、分开读回**；因子按除权日生效（valid_from = 除权日），日期 D 的累计复权只用除权日 ≤ D 的因子（POINT-IN-TIME §5.4）。一字板判定只读原始价〔R7〕。

### 2.5 历史股票池

- BaoStock 按日期查询**当日全部上市股票**（含后来退市的），逐日重建当时的股票池，避免幸存者偏差。

## 3. 退市覆盖缺口声明〔R16b〕

BaoStock 按日期重建**当时股票池**（含后来退市的）是正确的，但其**退市股票的完整行情覆盖不全**（退市后历史区间的日线/因子可能缺失）。处置：

1. 用 **AKShare（东财接口）补充**退市股票的历史行情；
2. 补充后仍缺的，**如实标注 DATA_GAP**，进入封存 manifest 的显式缺口列表；
3. **不得静默跳过**：退市股票在历史参照库分母里照常在场，缺行情则该段样本按"数据缺口"单独分类，不冒充"无事件"，也不从分母里消失。

判定：任选已退市股票 × 缺失区间，读回结果要么有行情原件，要么有带范围的 DATA_GAP 记录；两者皆无即违约。DATA_GAP 的实际规模取决于 AKShare 对退市股的覆盖范围——实施时实测核对。

## 4. 三层回填策略〔R16c〕

一次性全量 PDF 回填（约 1500 只 × 11 年 × 每年 20–30 份 ≈ 30–40 万份、百 GB 级、数周抓取且有限流）不做；按三层推进：

| 层 | 范围 | 工程量级（粗估） | 完成判定 |
|---|---|---|---|
| **L1 全量公告元数据** | 中证 800 全部股票（含历史调出与退市，按 §2.5 重建）2015 至今的公告标题/时间/类别 | 30–40 万条元数据行（无 PDF 本体），抓取量与存储均低一个量级 | 任意抽样股票 × 日期的公告元数据可 as-of 读回；抽样与巨潮页面核对一致 |
| **L2 研究池全量 PDF** | 研究池 30 只的全部公告 PDF | 30 只 × 11 年 × 20–30 份/年 ≈ 7 千–1 万份 PDF，存储粗估数十 GB 以内 | 30 只公告 PDF 全部入 CAS、哈希可校验读回；研究封存不再依赖外站取原件 |
| **L3 事件驱动 PDF** | 中证 800 范围内六类事件的主证据公告，按需抓取 | 随事件命中数增长，由历史参照库样本量决定（P4） | 每条进入参照库/研究引用的事件，主证据要么有 PDF 原件，要么显式 DATA_GAP 并降级为"元数据级证据" |

**历史参照库的启动不等 L3**：六类事件用 BaoStock 预告/快报接口 + L1 公告元数据即可构建（数值受 §5 声明约束，主证据标"元数据级"）；L3 按需把关键样本升级为 PDF 级。

## 6. 适配器规则

1. **独立适配器 + 独立版本号**：每个来源一个独立适配器（巨潮、BaoStock、AKShare、交易所官网、中证校验、申万），各自持有独立版本号，对应"数据与适配器版本轴"（`docs/ARCHITECTURE.md` 约束 3）。每条事实带 source_evidence_ref / source_hash / adapter_version（POINT-IN-TIME §2.1）。
2. **适配器不决定业务语义**：适配器只做"取数 → 解析为带时间字段的事实 → 写原件库"；什么构成事件、涨跌停怎么判、行业基准怎么选，分属 `ASHARE-RULES.md` / `RESEARCH-METHOD.md` / `HISTORICAL-REFERENCE.md`。来源原生字段（如公告类别标签）原样保存，不做业务改写。
3. **解析合同变更**：可用**同一原件重解析**生成新事实版本——新 fact_id、新 available_at、新 adapter_version，旧事实保留，不重写历史（POINT-IN-TIME §4）。同原件 + 同适配器版本重放不产生新 fact_id，只加观察收据。
4. **来源注册是静态的**（思想参照 `/Users/yeemio/AI/gitrep/metis/packages/catalog-evidence/README.md`）：来源与抓取合同在配置中静态登记，适配器运行时不能自我登记新来源或修改抓取合同；来源合同变更走新适配器版本，不在运行中热改。
5. **来源重复键去重**。去重键 = `provider + resource + 对象标识 + 新鲜度窗口`：
   - provider：来源方（cninfo / baostock / akshare / sse / szse / csi / cni / sws 等）；
   - resource：来源下资源类别（announcement_pdf / daily_kline / adjust_factor / index_constituents / quarter_financial / forecast / express / margin / dragon_tiger / sw_classification 等）；
   - 对象标识：资源内唯一键（证券代码+日期、公告 ID、代码+报告期、指数代码+日期）；
   - 新鲜度窗口：该对象取值是否仍可能变化——历史日线/复权因子/成分/分类版本为**已终局窗口**，窗口关闭后不再自动重抓；财务数值为**可变窗口**（来源侧仍会修订）。
   - 判定：窗口内同键重复采集命中去重，不重复入库、不重复解析；已终局对象重抓发现 bytes 变化时不覆盖，按来源冲突登记（POINT-IN-TIME §4）；可变窗口（财务）发现数值变化时生成新事实版本（supersedes 链），不当作重复丢弃；适配器版本变更的重解析不受去重阻挡。

## 7. 限流与退避〔R15〕

**数据源层退避**（与执行内核 EK-7.2 的模型层退避相互独立）：同一调用遭遇限流/超时/临时不可用时，首次等待约 **30 秒**，逐次加倍（约 30s/60s/120s），**至少重试 3 次**；3 次仍失败则停止重试、按**暂停上报**，上报四要素：**已重试次数、最后错误、恢复位置（断点）、唯一下一步动作**。瞬态问题不升级为任务失败；恢复后从断点继续，先读回最后一步的实际结果再续跑。

**主动并发限流**：我方采集任务同时 **≤2–3 个**（与全局并发纪律一致）；对单一来源的并发进一步收敛到串行或低并发——具体数值按各来源实测结果登记（下表），不拍脑袋设高。

**各来源已知限流特性如实登记，不夸大不缩小**。下表登记的是"实测到的行为"，不是来源方的承诺；来源方无公开限流政策的，如实写明：

| 来源 | 已知特性（v1 登记） | 实测状态 |
|---|---|---|
| 巨潮资讯网 | 公开网站，未见正式公开的抓取限流承诺；集中高频抓取存在被临时限制的风险 | P1 实测后回填实际可用速率 |
| BaoStock | 免费 SDK，需先登录建立连接；官方未公布明确速率上限；串行低速率调用为稳妥默认 | P1 实测；连接断开的自动重连行为一并实测 |
| AKShare | 聚合东方财富等公开网页接口，限流与反爬随上游网站策略变化，无统一承诺 | P1 实测并定期复核；上游改版即触发适配器新版本 |

判定（合成注入）：注入连续 3 次可恢复限流错误，观察到的等待序列约为 30s/60s/120s 且第 4 次不再发起，采集任务状态为暂停上报（含四要素）而非 FAILED。

## 8. 风险声明

BaoStock 与 AKShare 是**第三方免费工具**：接口可能变更或失效、可能限流、数据可能有错；交易所官网与巨潮也可能调整页面与栏目。处置方式（全部为已建机制，非安慰性声明）：

1. **适配器版本化**（§6）：来源改版时以新适配器版本吸收，历史事实不重写；
2. **原件本地保存**（POINT-IN-TIME §9）：一旦取得原件，来源后续变化不损坏已入库证据；
3. **关键数字与公告原文交叉核对**：进入研究结论与参照库主证据的关键数字，以公告 PDF 原文为准做交叉核对（§2.2、§2.3、§5）；
4. **仅个人用途**：数据与原件不外传、不对外分享（`docs/PLAN.md` §9 合规边界）。

| 投资者互动平台（互动易、上证 e 互动） | 非首版必需 | **二版候选**，登记不实施 |

## 10. 验收判定（P1 停止条件的数据侧表达）

P1 停止条件（`docs/PLAN.md` §8）：**30 只研究池 + 中证 800 能按任意历史日期完整封存，且不泄漏未来信息**。数据侧表达为：

1. **覆盖读回**：对抽样历史日期集合（含财报季边界日、指数成分调整日、行业版本切换日、退市前后日）× 研究池 30 只 + 中证 800 抽样股票，能构建封存 manifest，且 §2 各行的数据（公告元数据、L2 范围内 PDF、日线与因子、成分、分类、财务、预告/快报）均可 as-of 读回；未覆盖处逐一以 DATA_GAP（§3）或后置项（§2.9）出现在 manifest 显式缺口列表，无未声明缺口。
2. **缺口读回**：退市覆盖缺口、首版后置项、不做项（§9）在读回与界面中可见可查，不静默。
3. **不泄漏**：泄漏测试本体在 POINT-IN-TIME §8（四类时点对象 + 边界用例）；本合同的数据侧义务是供给该测试——四类对象的真实数据合成用例、截点当日公告的两条路径（时刻可得 / 日精度 D+1）、预约披露表版本切换用例全部可执行且通过。
4. **修订口径**：适配器输出与消费方模板中可检索到 §5 声明原文（判定同 POINT-IN-TIME §6）。
