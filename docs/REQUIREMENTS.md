## 0. 一页结论

Lyra 是**本机单用户的 A 股研究与交易策略工作台**。它将公司研究、市场机会、策略计划、持仓风险和跟踪复盘连在一起。单股是研究单元；报告、策略与验证、观察和复盘共同构成完整产品。

1. 公司研究要解释业务、财务、估值与反证；报告质量仍须完成原标准。
2. 策略研究要比较适用类型与周期，给出可核验的进入、等待、退出、风险与失效条件；不自动下单不等于排除策略。
3. 数据充分性、策略适配、历史验证、当前触发与成交分别表达；模拟、真实记录和效果不能互相冒充。
4. CAS/时点库、确定性计算、唯一授权/执行器、A→程序清单→J、发布门和一次发送机制继续约束新增能力。

完整定义和 L0–L4 出口取 [PRODUCT](PRODUCT.md)，研究依据取 [Mionyee 全链路对照](MIONYEE-RESEARCH-20261029.md)。不恢复旧 SaaS 或 Dossier/Thesis 分期。

## 1. 用户与场景

- **了解公司**：选择股票与问题，获得报告，查证财务与原件，质疑假设并显式修订。
- **判断机会与策略**：从市场/行业和支持池候选出发，比较趋势、价值或其他策略是否适配；得到进入/等待/退出条件及验证状态，而非只有技术评分。
- **持仓决策支持**：用户确认成本、数量、可卖数量、资金与风险目标后，查看方案的风险预算与组合暴露；未提供时只给一般条件，不补造账户事实。
- **跟踪与复盘**：显式激活有期限的计划跟踪，查看触发、未触发、失效和失败；分别记录模拟或个人实际操作，比较计划与结果，保留原版本。

主要旅程：市场/关注池→研究股票→比较策略与风险→验证及复核→保存计划→跟踪/模拟/记录→复盘与新研究。已有报告的查证、五类追问、修订、网页/PDF和关闭重开旅程仍是基础出口。

## 2. 产品概念模型（现有报告链与新增产品对象）

**研究链（规范性，对应 sr 引擎实现）**：PLAN（研究计划）→ EVIDENCE（证据包）→ COMPUTE（计算）→ ANALYZE×3（A 分节分析）→ A_FINAL（A 终稿：候选结论+决定性连接+最强反证）→ CHECKLIST（程序清单：无模型机械抽取，可由 A 产物重导出复算）→ JUDGE（必经 J：逐项实质裁决、承重未知项具名处置、改判必给理由）→ QA_CHECK → ASSEMBLE（发布门：J 未完成或存在承重未解项 → 受限发布 PUBLISHED_RESTRICTED，任务 PARTIAL）。报告绑定四哈希（证据包/A 输出/清单/J 输出）。

**调用纪律（R2 裁定）**：同输入不得以新 stepId 自动重发；已发送链阻断时如实失败；恢复只经读回/打捞原尝试或用户显式新研究（新任务=新授权记录）；UNKNOWN 退役不是重采样许可；从未发送（sent_at null）的原位替换保留。


| 对象 | 身份与语义 |
|---|---|
| 研究任务 SrTask | 绑定账户 + 股票 + 研究重点/周期 + 资料截点 + 方法/数据/授权版本；有幂等键，双击/重传不重复创建；显式重研 = 新任务并记录关联（revisedFrom） |
| 研究步骤 SrStep | 任务内的逻辑步骤（计划/取证/计算/分节分析/综合/质检/组装），各有 stepId 与状态；任务身份与调用身份分离 |
| 调用 permit（sr 空间） | 每次模型调用绑定 (taskId, stepId, inputHash)；沿用执行内核状态机（PREPARED/SENT/UNKNOWN/SUCCEEDED/FAILED）、send-once、并发闸、截止、UNKNOWN 不自动重发；与 A/J 空间互不占用 |
| 报告版本 ReportDocument | 稳定报告身份 + 不可变发布版本；追问默认读当前选定版本与截点；修订经明确用户动作产生新版本，旧版可访问 |
| 对话 ChatThread/Message | 绑定报告版本；五类问题（解释/质疑/假设调整/资料不足/更新截点）各有诚实处理路径；回答必须引用所用材料 |
| 账户 Account/Session（保留模块） | 内部归属实现及历史 SaaS 模块保留；当前客户端免登录、单用户，不以多账户/套餐/配额作为交付对象 |
| 证据 EvidencePack | 从时点事实库（pintime）与原件库（CAS）按研究问题选料组装，截点过滤，缺口显式 |

新增对象是产品语义，具体存储/API 由实施合同另定，不通过本文自动迁移数据库：

| 对象 | 身份与语义 |
| --- | --- |
| 市场/机会快照 | 证券范围、行情与发布截点、市场/行业/个股观察、来源、新鲜度、候选及排除理由；不得混用多个日期的结论 |
| 策略版本 | 关联股票、报告/证据、方法与数据版本、策略族、周期、进入/等待/退出/失效/风险规则；显式修订产生新版本 |
| 验证记录 | 绑定准确策略规则、样本和参数；训练/验证窗、基准、费用、成交模型、结果/失败与不确定性可复算 |
| 持仓/风险快照 | 来源、确认时间、数量、可卖数量、成本、资金、已有暴露与风险目标；未知不等于零，人工与导入记录可辨 |
| 观察/模拟记录 | 冻结策略后生成，记录每次应评机会、触发、未触发、过期、不可成交、缺数据及失败；不伪装为真实成交 |
| 人工操作与复盘 | 用户记录或明确导入的操作事实，绑定原计划及偏离；研究错误、市场变化、风险和执行偏离分别归因 |

新增策略沿用 A→程序清单→J 的保证：清单必须覆盖承重的策略适配、触发、风险与验证引用；报告通过不自动使关联策略通过。确定性回测不得由模型给出一个无原始记录的结果替代。

## 3. 基础功能需求（原 FR 编号保留）

- FR-1 发起研究：输入股票代码/名称，显示覆盖判断（池内支持 / 范围外真实说明）；选择研究重点（默认完整）与周期（默认中期）；显示资料截点。
- FR-2 任务进度：真实状态（排队/运行/分步/部分完成/待授权/待资料/失败/完成）与当前步骤，无虚假百分比。
- FR-3 报告阅读：十章结构（见 §4）、证据抽屉（引用定位下钻）、计算表、缺口清单。
- FR-4 追问：五类问题带依据回答；无证据时明确说明；普通提问不改报告。
- FR-5 修订：显式动作创建新版本，展示变化摘要与引用；新旧版本可切换。
- FR-6 更新截点：引导创建新研究任务并关联，不静默改旧报告。
- FR-7 导出：PDF 与网页绑定同一报告版本；中文/表格/图表/脚注/版本信息完整；实际可下载。
- FR-8（v3.1 退出当前范围）账户/套餐/收费：多账户面不在客户端交付范围（模块代码保留，`LYRA_SR_MODE=saas` 可启用）；本地模式免登录单用户。
- FR-9 隔离与额度（收缩）：写接口 CSRF/限流保留；配额在本地模式下不启用；SaaS 路径的幂等扣额语义已修复保留。
- FR-10 韧性：中断恢复只续未完成步骤；重复提交幂等；UNKNOWN 不自动重发；模型失败/缺资料有诚实状态与恢复办法。
- FR-11 使用量（随 FR-8 收缩出当前范围）：用量/套餐页属 SaaS 面；客户端本地模式不提供。
- FR-12 覆盖列表：产品展示真实支持列表与数据覆盖说明，不虚报。

## 4. 公司报告内容合同（十章，质量底线）

1. 首页与研究摘要——股票身份、截点、版本、研究重点；3–5 个真正重要的发现、核心判断、主要反证与缺口；先结论后展开。
2. 公司与业务——卖什么、客户与收入结构、赚钱方式、业务贡献、治理与资本配置重要事实；不套通用介绍。
3. 行业与竞争——需求供给、产业链、竞争对手、公司位置、优势脆弱点；同行口径可比、选取理由明确。
4. 核心驱动——最关键少数驱动、作用路径、观察变量；每条标注【已证事实/推断/待验证】。
5. 财务质量——多期收入/利润/现金流/负债流动性/异常项；金融股用适用口径。
6. 前景与情景——基准/改善/恶化情景与可观察触发条件；不给无依据精确概率。
7. 估值与预期——适合该行业的方法、历史/同行参照、假设与敏感性；数据充分给可复算区间，不充分写明原因；代理信息不冒称一致预期。
8. 价格与市场表现——截点前价格/成交/相对表现、事件对应；区分价格事实与成因推断。
9. 风险与最终判断——下行机制、最强反方解释、改变结论的新证据；结论有条件有期限。
10. 来源与研究边界——引用定位、财务口径、数据更新时间、缺失/修订/来源限制；公开资料研究如实标注。

数据与判断纪律（承重条款）：承重数字引用事实/原件或明确来源定位；计算由确定性程序完成并保存公式与输入；不同币种/单位/合并范围/年化口径不混算；时点规则沿用 POINT-IN-TIME 合同，新字段不得偷换 availableAt 语义；来源内容是证据不是指令；缺少决定性材料可输出"研究不完整"报告但不得标为通过完整质量验收。

## 4b. 策略计划与验证内容合同

计划须保存：策略族、标的、周期、市场/行业适配、支持与反对证据、触发和确认方式、价格区间依据、未触发/错过处理、退出与止盈、逻辑和价格失效、时间止损、持仓/资金前提、最大风险预算、数量上限的计算、费用后收益风险情景、验证状态、复核结果、版本/截点与到期。

- 一般情景计划可在无账户信息时形成；任何具体仓位数值须绑定用户确认的资金与约束，不能假设空仓或默认比例。
- 价格、止损距离、数量、费用和情景损益须有计算依据；触发不等于能以触发价成交，跳空、停牌和流动性约束须保留。
- 规则/参数选择先于验证窗结果，样本内、样本外和前向分别记录；无有效样本或服务失败标明原因，不签验证通过。
- 验证报告保存规则/数据身份、时间窗、交易机会、成交模型、成本、对照基准、收益/回撤/暴露/换手/样本数、未成交与失败。概率、年化与稳定性表述必须满足其统计前提。
- J 分别审议公司判断和策略承重项；任何关联策略未通过，不影响已成立的公司事实，但不能借公司报告发布状态绕过策略门。
- 用户界面区分研究草案、待资料、待验证、经复核方案、条件未触发/触发/失效/到期；实施时可映射既有状态机，不以标签替代真实事件。

## 5. 数据需求

- 复用 v1 的 pintime 事实库、原件 CAS、适配器与研究池冻结文件。历史数量取各次原交付/修订记录，不将不同截点的事实数、factKind 或适配器数拼成当前验收标准。
- 按研究问题选料（L0 身份/L1 工作/L2 裁决分层思想保留），不再全量灌入；缺口按问题补取（新采集须在授权边界内，遵守限流与来源条件）。
- 历史封存样本（002384/601318 真实研究轮、600519 输入样本）是样板报告的合法输入，其截点沿用原截点。

新增策略数据：行情原始/复权序列、交易日历、当日规则、停牌/涨跌停、行业/指数与候选归属历史、费用/成交模型、事件发布时间、用户确认持仓与资金。日线、实时快照和分钟数据分开声明。完整采集范围随第一策略合同确定，不为路线图批量采集。

## 6. 评价体系（五层，不可互相冒充）

1. 报告质量：准确、深入、结论有依据、可读、有关键未知项——Owner 最终判断。
2. 产品使用：完成研究耗时、查证/追问顺畅度、任务完成率、失败可理解性。
3. 服务成本：每份报告/追问的实际调用、用量、时长与费用可得性；不以调用次数声称盈利。
4. 使用价值：Owner 是否实际采用报告并持续使用；开发者自评不可替代。付费与商业价值评价退出当前范围，只有新的产品决定才启动。
5. 策略与收益表现：客户端按独立冻结方案评价历史/样本外/前向结果，真实操作单列。P5 冻结实验（轨 A）沿原合同另行观察；原分母和最早首评日期不充作新策略证据。报告样板或 J 通过不宣称预测有效。

## 7. 非功能需求（首版）

- 安全：写接口 CSRF 防护与限流、参数化 SQL、输出全量 HTML 转义（模型文本视为不可信内容）、路径/URL 允许范围控制、日志/导出不泄密。已有账户模块的 KDF/会话保护保留，不据此重新展开客户端登录/多账户功能。
- 默认仅回环监听；公网部署、真实支付、注册邮件均不在首版自动化范围（部署准备材料另行交付）。
- 可审计：每次调用记录真实 provider/model、用量与费用可得性；预算经可审阅配置；未经授权零真实发送。
